# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A [Docusaurus](https://docusaurus.io/) v3.5 static documentation site ("DSO Live Demo Docs") used as a developer-blog/knowledge-base template. Content is authored as Markdown/MDX; there is no application backend and no test suite.

## Commands

Local development uses **pnpm** (CI uses npm — see note below):

```bash
pnpm install          # install deps
pnpm start            # dev server with hot reload at http://localhost:3000
pnpm build            # build static site into build/
pnpm serve            # serve a completed build locally
pnpm typecheck        # tsc — the ONLY automated check in this repo (no tests exist)
pnpm clear            # clear the Docusaurus cache (.docusaurus/) when things get weird
```

There is no lint or test runner configured. `pnpm typecheck` is the closest thing to a validation gate; `pnpm build` also fails on broken content (see below).

## Configuration is environment-driven

`docusaurus.config.ts` reads its deployment identity and feature flags from environment variables via `dotenv`, so behavior differs by environment:

- `pnpm start` / `pnpm build` with **no `.env`** falls back to hardcoded defaults (`baseUrl: "/"`, `spmse` org). This is fine for local previewing.
- A **real build** for deployment expects `example.env` copied to `.env` (`cp example.env .env`) — this is exactly what `deploy.yaml` and the NGINX Dockerfile do. `.env` sets `BASE_URL`, `DEPLOYMENT_URL`, `GITHUB_ORG`, `GITHUB_PROJECT`, `DEPLOYMENT_BRANCH`.
- **`BLOG_ENABLED`** (default `false`): the `/blog` section, its navbar/footer links, and the blog preset are conditionally wired up at the bottom of `docusaurus.config.ts`. When toggling blog behavior, edit both the preset block and the `if (blogEnabled)` block that mutates `navbar`/`footer`.

## Content architecture

- **`docs/`** — all documentation, grouped into `guides/`, `knowledge-base/`, and `projects/`. The sidebar (`tutorialSidebar`) is **fully autogenerated** from the folder tree (`sidebars.ts` uses `{type: 'autogenerated', dirName: '.'}`), so:
  - Ordering is area-specific: `docs/knowledge-base/` sorts by **numeric filename prefix** (`00-overview.md`, `01-...`), while `docs/guides/` sorts by **`sidebar_position` frontmatter**. Don't mix the two conventions across areas.
  - Each directory's label/position comes from a `_category_.{json,yaml,yml}` file (note: extensions are inconsistent across dirs, all are valid).
  - Adding a doc requires no config change — just drop the file in.
  - For turning pasted notes/screenshots into new `docs/knowledge-base/` pages, follow `.claude/authoring-playbook.md` — it has the full procedure (placement, transcribe-vs-embed for screenshots, category templates) and a worked example at `docs/knowledge-base/python/`.
- **`blog/`** — blog posts (only surfaced when `BLOG_ENABLED=true`). Authors/tags live in `blog/authors.yml` and `blog/tags.yml`.
- **`src/`** — custom React/TS. `src/components/` holds reusable MDX components (e.g. `GithubLinkAdmonition`, documented for authors in `docs/guides/nodejs/GithubLinkAdmonition.md`); `src/css/custom.css` holds theme overrides; `src/pages/` holds standalone pages.
- **`static/`** — served verbatim at site root (referenced as `/img/...`).

`onBrokenLinks: 'throw'` — a broken internal link **fails `pnpm build`**. Verify links when moving or renaming docs.

## Deployment

Two paths, both build the static site first:

- **GitHub Pages** (`.github/workflows/main.yml` → `deploy.yaml`): triggers on push/PR to `main`; deploys only when on the default branch. Copies `example.env` → `.env`, builds, uploads a Pages artifact. Manual equivalent: `USE_SSH=true pnpm deploy`.
- **Docker + NGINX** (`Dockerfile`): multi-stage build → static files served by `nginx`. Build args mirror the `.env` vars. See `docs/guides/deploy-docusaurus-with-docker-and-nginx.md`.

`create-pr.yaml` auto-opens a PR against `main` for any push to a non-default branch.

## Conventions

- **Commits follow Conventional Commits** (`<type>[scope]: <description>`), documented in `docs/knowledge-base/git/03-conventional-commits.md` and consistently used in history. Use types like `feat`, `fix`, `docs`, `ci`, `chore`, etc.
- **pnpm locally, npm in CI**: the README and lockfile (`pnpm-lock.yaml`) target pnpm, but the GitHub Actions workflows run `npm install`. Keep both dependency states coherent when changing `package.json`.
